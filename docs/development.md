# Development

## Requirements

- A JDK, 17 or newer (the pom compiles for 17; CI runs 25). Maven comes with the wrapper (`./mvnw`).
- A Rust toolchain: the tests compile and run generated crates with cargo, `cargo clippy -- -D warnings` included.
  Without cargo those tests are skipped.
- The `wasm32-unknown-unknown` target (`rustup target add wasm32-unknown-unknown`) for `WasmTest`, which checks
  generated crates for WebAssembly; without it that test only checks the files.
- Docker only to build the image. The tests do not need it.

## Building and testing

```bash
./mvnw test      # the whole suite, about 2 minutes once the Rust dependencies are compiled
./mvnw verify    # the same, plus the jar
```

The tests generate in-process from the specs in `src/test/resources/`. Crates generated by the tests build against
the runtime of the same commit (`runtime/`, through the `timvw-rust.runtimePath` system property the pom sets), and
share one cargo target directory, `target/cargo-target` (`CARGO_TARGET_DIR`), so their dependencies compile once per
run. A test-only cargo shim, `src/test/bin/cargo` (put first on the tests' `PATH` by the pom), removes the crate under
test from that directory before each cargo command, as several tests generate crates with the same name. Remove
`target/cargo-target` to reclaim the disk space.

Each rule of the [mapping](mapping/README.md) links the tests that show it (`MappingDocsTest` checks the links;
`python3 tools/link-mapping-tests.py` rewrites their line numbers). The Rust tests in `src/test/rust/*.rs` run
against generated crates. The documentation is tested too:

| Test | Checks |
| --- | --- |
| `DocsExamplesTest` | every ```` ```rust ```` block of `README.md` and `docs/guides/*.md` is in `src/test/rust/docs_examples.rs`, which compiles and runs against a crate generated from `src/test/resources/docs_examples.yaml`; a block that is not meant to compile is preceded by `<!-- not compiled: reason -->` |
| `DocsLinksTest` | every relative link of `README.md` and `docs/**/*.md` points at a file and heading that exist |
| `MappingDocsTest` | every rule of `docs/mapping/` names tests that exist |
| `OptionsDocsTest` | every option of the generator, and every name it rejects, is in [options.md](options.md) |

To try another openapi-generator version: `./mvnw -Dopenapi-generator.version=<version> verify`.

The runtime is a cargo crate of its own:

```bash
cd runtime
cargo test --all-features
cargo clippy --all-targets --all-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo hack doc --no-deps --each-feature # docs build with any features
RUSTDOCFLAGS="-D warnings" cargo hack doc --no-deps --each-feature --target wasm32-unknown-unknown
cargo clippy --target wasm32-unknown-unknown --no-default-features --features reqwest,retry,tracing -- -D warnings
```

Its README's examples are doctests. `tests/wasm.rs` runs in Node.js with `wasm-bindgen-test-runner` (see the `wasm`
job of the CI workflow).

## The image

Build the image and generate the petstore smoke test with it:

```bash
./mvnw -DskipTests package
docker build --build-arg OPENAPI_GENERATOR_VERSION=7.27.0 -t timvw-rust:dev .
docker run --rm -v "$PWD:/local" -u "$(id -u):$(id -g)" timvw-rust:dev generate -g timvw-rust \
  -i /local/test-specs/petstore.yaml -o /local/target/petstore --additional-properties=packageName=petstore
cargo build --manifest-path target/petstore/Cargo.toml
cargo check --target wasm32-unknown-unknown --manifest-path target/petstore/Cargo.toml
```

To build against another openapi-generator version, pass it to Maven first
(`./mvnw -Dopenapi-generator.version=<version> package`) and then to `--build-arg`.

## CI

`.github/workflows/ci.yml` runs on every push and pull request:

- `build`: `./mvnw verify` (with the `wasm32-unknown-unknown` target installed, and `target/cargo-target` cached),
  the generator listed by the stock CLI, the image, and the petstore generated with both HTTP stacks, built, and
  checked for `wasm32-unknown-unknown` (tower).
- `runtime`: `cargo fmt --check`, clippy, `cargo test --all-features`, each feature on its own (`cargo hack`), the
  docs with `-D warnings` without default features and with each feature, and `cargo publish --dry-run`.
- `wasm`: the runtime for `wasm32-unknown-unknown`: clippy, each feature on its own, its docs with each feature, and
  `tests/wasm.rs` in Node.js.

## Templates

The templates are in `src/main/resources/timvw-rust/`. They started from the `rust` templates of openapi-generator
7.27.0 (see [NOTICE](../NOTICE)) and are edited by hand like the Java code. None is looked up in the openapi-generator
jar.

## Layout

```text
src/main/java/be/timvw/openapi/rust/     RustCodegenBase (Rust types, naming, model and operation processing),
                                         TimvwRustCodegen (options and rules) and the rule classes
src/main/java/org/openapitools/codegen/  same-package access to the inline-model resolver and the normalizer
src/main/resources/timvw-rust/           every template the generator renders
src/test/java/, src/test/resources/      JUnit tests and the specs they generate from
src/test/rust/                           Rust tests run against generated crates
src/test/bin/cargo                       the tests' cargo shim
runtime/                                 the timvw-rust-runtime crate
docs/                                    guides, options, the mapping, comparison, decisions, design, history
tools/                                   link-mapping-tests.py, check-default-rule.py, check-union-samples.py
test-specs/petstore.yaml                 smoke-test spec
Dockerfile                               the openapi-generator CLI and this jar on a JRE
```
